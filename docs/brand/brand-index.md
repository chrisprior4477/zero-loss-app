# Repository Priority

This document serves as the entry point into the ZeroLoss Brand Operating System.

It should be read before any other document in the `docs/brand/` folder.

Unlike the other Brand documents, this file does not establish philosophy or implementation guidance.

Its responsibility is navigation.

It explains how the Brand System is organized and how every Brand document contributes to the overall customer experience.

---

# Purpose

The ZeroLoss Brand System is intentionally divided into multiple governing documents.

No single document attempts to explain every aspect of the brand.

Instead, each document owns a specific responsibility.

This approach makes the Brand System:

- easier to maintain
- easier to understand
- easier to expand
- easier for AI systems to interpret
- easier for future contributors to navigate

Every Brand document should answer one category of questions exceptionally well.

No document should duplicate the responsibility of another.

---

## 1. What Is the Brand Operating System?

The Brand Operating System is the complete collection of documents that define how ZeroLoss presents itself to the world.

Together these documents establish:

- identity
- philosophy
- customer experience
- communication
- visual language
- implementation guidance
- governance

Collectively, they ensure that every customer experiences ZeroLoss consistently regardless of platform, device, campaign, or future product.

The Brand Operating System exists to eliminate ambiguity.

Future contributors should not invent the brand.

They should implement it.

## 3. The Role of Each Document

Every document has one primary responsibility.

**Brand Identity**

Defines who ZeroLoss is.

Establishes the Brand Promise.

Defines the company's long-term philosophy.

---

**Experience Manifesto**

Defines how customers should feel.

Explains the emotional objectives behind every interaction.

---

**Marketing & Messaging**

Defines how ZeroLoss communicates.

Establishes messaging architecture, terminology, voice, and campaign guidance.

---

**UI Brand Bridge**

Connects the brand philosophy to interface design.

Explains how screens, layouts, and interactions reinforce customer confidence.

---

**Motion Principles**

Defines how movement communicates.

Explains how animation should guide attention, reinforce trust, and improve understanding.

---

**Color System**

Defines how color communicates.

Establishes semantic meaning rather than specific palettes.

---

**Typography**

Defines how written information communicates.

Explains hierarchy, readability, rhythm, and comprehension.

---

**Iconography**

Defines how symbols communicate.

Explains how icons improve recognition, navigation, and customer confidence.

---

**Imagery & Photography**

Defines how visual assets communicate.

Establishes the philosophy for photography, illustrations, and supporting imagery.

---

**Logo Standards**

Defines how the ZeroLoss logo is protected.

Establishes the long-term rules for official logo usage and future brand marks.

---

**Brand Asset Governance**

Defines how brand assets are managed.

Establishes ownership, approvals, version control, and long-term governance for the entire Brand System.

## 4. Relationship to the Rest of the Repository

The Brand folder does not exist independently.

It supports every other major area of the ZeroLoss repository.

Brand decisions influence:

- Architecture
- Product Specifications
- Design System
- Operations
- Marketing
- Customer Support
- Analytics
- Administration

Likewise, those documents should respect the principles established within the Brand System.

The Brand folder answers:

**"How should ZeroLoss feel?"**

Other repository documents answer:

**"How should ZeroLoss work?"**

Both are required to create a consistent customer experience.

## 5. Relationship to the Design System

The Brand System establishes philosophy.

The Design System establishes implementation.

For example:

The Brand documents define:

- what trust looks like
- what confidence feels like
- how communication should work

The Design System defines:

- spacing tokens
- component specifications
- color values
- typography scales
- interaction patterns

The Brand System answers **why**.

The Design System answers **how**.

Neither replaces the other.

## 9. Avoiding Duplicate Guidance

Every Brand document has a defined responsibility.

Future contributors should avoid copying guidance between documents.

Instead:

Reference.

Link.

Build upon.

Do not duplicate.

Duplicated guidance eventually creates conflicting guidance.

A document should own its subject.

Other documents should reference it.

This keeps the Brand System maintainable over time.

---

## 10. Relationship to AI Assistants

AI systems are expected to become long-term contributors to the ZeroLoss project.

Before generating customer-facing work, AI assistants should understand the Brand System.

AI should not invent:

- new messaging
- new terminology
- new color meanings
- new icon meanings
- new interaction philosophies

without first checking the governing Brand documents.

AI should implement the Brand.

Not redefine it.

Whenever multiple technically correct solutions exist, AI should choose the solution most consistent with the ZeroLoss Brand System.
